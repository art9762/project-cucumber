On 2026-06-05 built **Phase 3 (research)** and **Phase 4 (embeddings + analysis API)** of `analysis/` IN PARALLEL via a **7-agent swarm** (3 research + 4 embed) on disjoint files. I (integrator) first locked the shared foundation so agents never raced: ORM, migration, Trinity method, config, frozen contracts, specs, conftest, deps.

**Phase 3 — research:** by-idea web analysis + competitor search. Uses the **native Anthropic `web_search_20250305` server-tool, proxied by Trinity** (verified live — no external search provider, no new secret). Model default = Sonnet (`research_model`), runs on selected/important items not the whole stream. Files in `analysis/research/`: `models.py` (frozen: `Competitor`/`ResearchResult`/`ResearchStats`), `prompt.py` (`build_research_prompt`/`parse_research`), `selector.py` (`select_unresearched_items` — has item_analysis, no item_research row; filters `min_tier`/`min_coefficient`, order coef DESC), `researcher.py` (`run_research(*, analysis_sessionmaker, trinity, limit, min_tier, min_coefficient, model, max_searches)` — mirrors scorer.py, SAVEPOINT per item, INSERT item_research), `__main__.py`. API: `api/research_schemas.py` + `routers/research.py` (`GET /items/{id}/research` 404-if-none, `GET /research?has_competitors=`, `POST /research`).

**Phase 4 — embeddings + API:** **LOCAL embeddings (fastembed `BAAI/bge-small-en-v1.5`, CPU, 384-dim, no API)** + **pgvector** — chosen by user because Trinity has NO embeddings endpoint (404 on all variants) and stock postgres:16 lacked pgvector. Files in `analysis/embed/`: `models.py` (frozen: `EmbedStats`/`SearchHit`), `encoder.py` (`Encoder` lazy-loads fastembed, `build_embed_text`, `cosine_distance`), `selector.py` (`select_unembedded_items` — no item_embeddings row), `embedder.py` (`run_embedding(*, read_sessionmaker, analysis_sessionmaker, encoder, limit)`), `__main__.py`. `embed/search.py` is **dialect-aware**: Postgres uses pgvector `<=>` via `text()`; SQLite (unit tests) uses Python cosine — so tests need no Postgres. API: `api/search_schemas.py` + `routers/search.py` (`POST /search` smart search, `GET /items/{id}/competitors`, `POST /embed`; Encoder is a lazy module singleton, never built at import).

**Foundation I built (NOT agents):** `storage/orm.py` +`_Vector` TypeDecorator (pgvector `Vector(384)` on PG / JSON on SQLite), `EMBEDDING_DIM=384`, `ItemResearchORM` (summary, competitors JSONB, sources, maturity_signal, potential_signal), `ItemEmbeddingORM` (embedding, model, dim). Migration **`0002_research_embeddings`** — `CREATE EXTENSION vector`, both tables, ivfflat cosine index. `trinity.py` +`search_complete(messages, *, model, max_tokens, system, max_searches) -> (text, source_urls)` (drives web_search, collects source URLs). `config.py` +`research_model`/`research_max_searches`/`embedding_model`/`embedding_dim`. `main.py` +research+search routers. `pyproject.toml` +`pgvector>=0.3`,`fastembed>=0.3`. conftest registers both new ORM models. `search engine/docker-compose.yml`: **image `postgres:16` → `pgvector/pgvector:pg16`** (drop-in; pgdata volume preserved, the 60 items survived recreate; ran `ALTER DATABASE findengine REFRESH COLLATION VERSION` to silence libc warning).

**Two bugs I fixed at integration** (agents green in isolation, broke in full suite/live): (1) `test_search_api.py` used `sys.modules.setdefault` to inject fake embed modules — no-op'd once sibling tests imported the real modules first → rewrote to `patch.object` the real `embed.search`/`embed.embedder` attributes (router lazy-imports them inside handlers). (2) `embed/search.py` Postgres path did `str(query_vec)` but fastembed returns **numpy float32** whose repr `np.float32(...)` pgvector can't parse → added `_vector_literal()` that coerces each element via `float()`.
